# Fixes

Things that need fixing in reWork itself (tools, templates, skills), and things already fixed. Add to Open when you find something; move to Fixed with what was wrong and what changed. Same commit as the change.

## Open
- Skills and tools are untested end to end on a real target; run the benchmark in README.md and record gaps here.
- `tools/setup_tools.py` pins jadx and apktool versions and verifies SHA-256 only when `JADX_SHA256`/`APKTOOL_SHA256` are set (it prints the computed hashes); the JDK is the latest 17. Pin real hashes once a machine with github access has downloaded them.
- Windows is untested locally: CI covers `rebuild_analysis.py` and `setup_tools.py`, but the fake-jadx tests skip there and a real run on Windows has not happened. macOS is likewise untested locally (the JDK bundle layout is unit tested).
- The ipa and firmware kinds of `rebuild_analysis.py` verify the hash only.
- Cloud sessions: apkpure, adoptium and github release hosts are blocked unless the environment allows them (README, AGENTS.md).
- iOS, desktop and firmware notes in the skills are thin.
- Vendor stack UUIDs and white-label rows in `re-watch-targets/references/vendor-stacks.md` now carry public sources from an external review, but nobody here has read those sources; check them on the first target that uses each stack.
- The unicorn harness does not apply relocations; add R_AARCH64_RELATIVE handling the first time a real library needs it, with a test.
- `tools/scrub_capture.py` matches `--mask` hex at any nibble offset; a match straddling a byte boundary would mask the wrong nibbles. Rare; align to even offsets if it bites.

## Fixed
- reWork was behind reWatch PR #3 (2026-10-14): ported the skill upgrades (triggers, gate map, unicorn rules and harness, framework triage, Protobuf/TLV, ABI split, vendor stacks, re-watch-targets), `tools/scrub_capture.py`, `rw.py taskflags`, the safe-write reference and their tests by a three-way merge that kept reWork's own generic wording.
- Skills copied from reWatch (`re-jieli`, `re-ble-android-patterns`, `re-capture-ingestion`), `tools/notify_log.py` and the README examples named a specific badge or watch: reworded to generic devices and a placeholder slug; device notes stay in `knowledge/` (2026-10-12).
- Skill suite review (2026-10-14): descriptions named gates instead of what a user asks, so a skill did not trigger without `re-workflow`; re-workflow sent readers to AGENTS.md for the gate-to-skill map and the tag legend; generic unicorn rules lived only in `re-jieli`; `re-static` and `re-ble-android-patterns` duplicated decompiler fallback and stored-key text; no framework triage (Flutter, React Native/Hermes), no Protobuf/TLV recovery, no ABI-split record rule, no capture scrubber, no reference guard code, no check that task-pack flags exist. Changed: all descriptions rewritten with user phrasing; gate map and legend in re-workflow (legend copied from AGENTS.md, SDK code stays `[C]` with an "SDK:" note instead of a new tag); unicorn rules table and `scripts/unicorn_aarch64_harness.py` (tested on a synthetic ELF) in re-native-emulation; boundaries split; framework triage in re-static; RxAndroidBle/Nordic/coroutine patterns; Protobuf/TLV section; ABI split rule in re-acquire; `references/vendor-stacks.md` and a white-label table; `tools/scrub_capture.py`; `re-client-sim/references/safe_write_and_link.py` (fails closed on an unreadable ledger, OTA/DFU blocklist, atomic save); `rw.py taskflags`. Tests for each new script.
- Pinning was only a hash check: added the pin rule to AGENTS.md, `COPY_LOCATION` and URL2 guidance in the SOURCES template, pin warnings and clearer mismatch and accept messages in the rebuild tool, with tests.
- Hash mismatch after a vendor update now names the real version; URL2 to URL4 fallbacks; rebuild-only-when-necessary and record-after-every-pass rules in AGENTS.md and the skills; QUICKSTART in the task-pack template; test that scripts mentioned in docs exist.
- Hardware recon had no reusable form that a weaker agent could follow: added `templates/tasks/` (README, SW-RECON, HW-RECON, ASSUMPTIONS, STATUS) copied by `rw.py init`, the `re-hardware-recon` skill, `tools/notify_log.py`, `tools/make_test_media.py`, and rules in `re-client-sim` (log pushed status, no-delta option) and `AGENTS.md` (writing for weaker agents). Derived from the reBeamBox task pack.
- Rebuild and setup were bash-only (`sha256sum`, `declare -A`, linux-x64 JDK URL), so they failed on macOS and Windows: rewrote both in Python 3 standard library (`rebuild_analysis.py`, `setup_tools.py`), kept the .sh files as wrappers, added OS/arch detection, the macOS JDK bundle layout, zsh PATH line, apktool.bat, and tests.
- jadx was OOM-killed on small machines and the cap lived only in the log: `rebuild_analysis.py` takes `--max-heap`/`JADX_HEAP` and defaults to 3g under 8 GiB RAM; an OOM kill now says so.
- `?version=latest` URLs break the hash check on a new release: `--url` overrides the download URL.
- No script rebuilt a target's artifacts and decompiled tree on another machine: added `tools/rebuild-analysis.sh` (SOURCES driven, hash-verified, idempotent), a machine-readable block in `templates/SOURCES.md`, and pinned jadx and apktool in setup-tools.
